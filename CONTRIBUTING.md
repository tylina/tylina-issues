# Submitting useful feedback / 提交有效反馈

Chinese and English are both welcome. Clear reports are more useful than long reports.

中文和 English 均可。信息准确比篇幅更重要。

## Bug reports / 问题报告

- Use a specific title that describes the visible problem.
- Include the exact Tylina version from **Tylina → About Tylina**.
- Include the operating system version and processor architecture.
- State which surface was active: Document, Split, Source Lens, Prefix Area, Presenter, or another tool.
- Start from the smallest `.typ` example that still reproduces the problem.
- Describe what happened and what you expected instead.

- 标题应直接描述可见问题。
- 从“关于 Tylina”中复制准确版本号。
- 写明操作系统版本与处理器架构。
- 写明当时使用的是文档、双栏、源码 Lens、前置源码区、演示窗口或其它工具。
- 尽量把复现文档缩减到仍能触发问题的最小 `.typ` 示例。
- 分别说明实际结果与预期结果。

## Attachments / 附件

Screenshots, short recordings, and minimal source examples are welcome when they make the behavior easier to understand. Before uploading, remove names, private paths, document content, credentials, package tokens, and any other sensitive information.

截图、短录屏和最小源码示例都可以帮助理解问题。上传前请删除姓名、私人路径、文档内容、凭据、包访问令牌及其它敏感信息。

## Feature requests / 功能建议

Describe the writing problem first, then the behavior you want. Explain where it should appear in the existing Document-first workflow. A concrete document example is usually more helpful than a list of controls.

请先说明写作中遇到的问题，再描述希望出现的行为，并说明它应如何进入现有的文档优先流程。一个具体文档例子通常比控件清单更有帮助。

## Pull requests

This repository tracks public feedback and its own repository documentation only. The Tylina desktop application source is not hosted here. Pull requests that claim to modify the application cannot be reviewed or merged.
